## Blocking

**B1 — `MissedDay.shiftMap` throws over stored rows (§4.2, §4.3, §5.3 case F, AC-20, AC-23).** INSIGHTS 2026-09-14 B2: "Engine functions over stored rows are total; validation belongs at the generator boundary only." `Reslot.reslot` (`/Users/zhabskyi/AppleApps/HomeGymLog/HomeGymLog/Engine/Reslot.swift:25`) already returns `[:]` for a non-pending index; the spec's `MissedDayError.sessionNotMissed` re-introduces throwing for a stale tap, and `invalidTrainingWeekdays` validates a field the generator already validated. It is also asymmetric with `skipMissed`, which returns `false` for the same stale case. A missed session is dated before today and is always re-dated to ≥ today, so its entry is always in the map; "empty ⇔ not missed" is sound.
*Change:* `shiftMap(...) -> [Int: Date]`, total; `[:]` when `missedIndex` is not pending-and-before-today (drop `invalidTrainingWeekdays`; if a guard against `CalendarRules`' precondition is wanted, return `[:]` there too). `ProgramStore.shift` returns the applied map, saves nothing when it is empty, and throws only on a failed save. Both surfaces treat an empty result as a silent no-op (like `WorkoutLogStore.start(sessionIndex:rows:)` returning nil, `/Users/zhabskyi/AppleApps/HomeGymLog/HomeGymLog/Models/WorkoutLogStore.swift:125`) and a throw as `assertionFailure`. Rewrite case F ("returns `[:]`, nothing written"), AC-20 and AC-23 ("a second call returns an empty map and writes nothing"). Otherwise a legitimate stale tap at 00:00 would trip `assertionFailure` in Debug.
*React:* an Engine function is a reducer; a reducer returns the unchanged state for an inapplicable action, it does not throw.

**B2 — "The overlay closes first, then the write" contradicts "derived from rows, never a one-shot boolean" (§2.2 rows 1–2, §3 "Prompt, save failed", §4.4, §6 "Failed save").** If "show it" is derived from rows + `now` + tab + silence, there is nothing to close: the only ways to hide it are to set the silence (then a failed save leaves the prompt hidden for the day, contradicting §3 "Prompt again (derived)") or to change the rows (which the write does). The NB4 precedent (swap pick closes the UIKit sheet before writing) exists because a UIKit sheet has presentation state; a derived overlay has none.
*Change:* delete the "closes first" step. The handler reads `clock.now()`, calls the writer, and the overlay disappears when the host's `@Query` re-fetches (the session is no longer missed). On a failed save the prompt **stays up** (Debug asserts; the user may dismiss it); on Skip with another missed session the card's content changes in place (the same instance renders the next `firstMissed`). Update §2.2 "Then" column, §3 row 4 and §6 "Failed save (either surface)" to match. A double tap is harmless: the second call finds the row not missed and writes nothing (B1).
*React:* render the modal from store state instead of an `isOpen` `useState` you must remember to flip back on error.

**B3 — Program-card shift "the same reset it performs on every return to the tab" breaks AC-15 (§2.4, §6 "Chips after a shift", AC-15).** `ProgramView.reset` (`/Users/zhabskyi/AppleApps/HomeGymLog/HomeGymLog/Features/Program/ProgramView.swift:58-66`) re-applies the DEBUG `preselection`. From `-seed missed -tab program -programWeek 2 -programDay 2`, a shift followed by `reset` re-selects WK 2 · Wed 9, now a rest cell, whereas AC-15 expects WK 3 · Tue 15 · "Legs" · "Today". Production (preselection nil) is unaffected, but the AC as written cannot pass in the scratch-copy XCUITest.
*Change:* the shift handler in `ProgramView` (next to `start`, it owns rows, clock and context) does `selection = .followToday; now = clock.now(); scrollToken += 1` directly, and only when the writer returned a non-empty map (a stale tap must not move the selection). Skip's handler refreshes nothing (selection stays, per §2.4). This is a handler write, never a `@State` write in `body`, so no "Modifying state during view update". Say "follows today (not `reset`, which re-applies the DEBUG preselection)".

**B4 — AC-13 and the case G / G′ half of AC-15 are unreachable (§8 Behaviour header, AC-13, AC-15).** Both need "midProgram data with today = Thu 09-17" (s7, s11, s12 missed). No seed freezes that day and a live clock cannot produce it during a test; taps are refused on this machine, so the scratch XCUITest is the only automated path. Separately, the header says "production launch, live clock" while AC-11, 12, 14, 15 all start from `-seed missed…`; the m3-rest-timer rule was about *time-dependent* behaviour, and nothing in shift/skip/dismiss depends on elapsed time, so seeds are the correct vehicle here — but the header must say so.
*Change:* add a DEBUG seed (e.g. `missed-3`: `MidProgramSeed` default rows, reference Thu 2026-09-17 12:00; joins `SeedNameScanTests`, `DebugSeedTests`, `SeedHomeStatsTests`) and point AC-13 and AC-15's G/G′ steps at it; or drop those UI steps to "covered by AC-20/22/24 unit tests + the user's MVP pass". Reword the header: "seeded launches (frozen clock) are used because no AC here depends on elapsed time; new-day transitions are edge cases verified by unit tests on `shouldPrompt`/`firstMissed`".

**B5 — Unverified: the host's `.onAppear` / `.onChange(of: scenePhase)` when its body renders nothing (§4.4 "always present (it draws nothing unless the rule holds)", §2.5 "Return to foreground", §6 "Backgrounded with the prompt up").** The researcher's `overlay-shell` mode attached the handlers to the `TabView` chain in `ShellView` with a `@State` there (report "Minimal example", Q1 evidence). It did not probe an always-mounted child whose body may collapse to `EmptyView`; SwiftUI does not run `onAppear` for `EmptyView`, and whether `.onChange(of: scenePhase)` fires on a view with no rendered representation is unverified. The new-day re-prompt (silence keyed on the day) depends on the scene-active refresh firing while the host is hidden.
*Change:* (a) the host's body root is a concrete container — `ZStack(alignment: .bottom) { if shows { scrim; card } }` — never a bare `if` that can become `EmptyView`, and it reads `now ?? clock.now()` (Home's pre-appear fallback) so the first frame is right even if `onAppear` is late; (b) mark it unverified in the spec with the probe: scratch copy, `-seed missed -tab program` (host mounted, hidden), background 1 s, `activate()`, assert a log line from the host's scene-phase handler on 17.5 and 26.5. If it does not fire, use the researcher-verified shape: `ShellView` owns `now` + the two handlers on the `TabView` chain and passes `now` into the host (ShellView stays cheap; a `now` write re-diffs the TabView, whose children take unchanged inputs).
*React:* in React a component that returns `null` still runs its effects; in SwiftUI a view that renders `EmptyView` may not run `onAppear` — that is the difference to probe.

**B6 — Unverified: a card drag that starts on one of the two buttons (§2.2 "Downward drag on the card", AC-14).** The researcher probed a scrim drag (Home did not scroll) and a system-sheet drag, never a `DragGesture(minimumDistance: 20)` on a container holding two 50 pt `Button`s. What happens when the finger lands on "Skip it · stay on schedule" and travels 100 pt down is unknown: if the button fires **and** the drag dismisses, a dismissal gesture writes a skip. The 20 pt minimum is borrowed from the scroll-conflict gotcha, which does not apply (the card is not inside a `ScrollView`); keep it, but it does not decide the button question.
*Change:* state the required semantics ("a drag beginning on a button never activates the button; ≥ 80 pt dismisses, less springs back") and mark them unverified with the probe in the plan's scratch-copy XCUITest: `press(forDuration: 0.1, thenDragTo:)` 120 pt down starting on the Skip button → prompt gone **and** s7 still pending; the same starting on the title → gone; 40 pt → still shown. If a button-origin drag misbehaves, restrict the gesture to the text block above the buttons (the prototype has no drag at all, so that is a legitimate fallback).

## Non-blocking

**NB1 — The third `@Query` and second `now` are the right duplication (§4.4).** Lifting Home's query to `ShellView` would make the shell a query owner re-rendering the whole `TabView` on every save, and passing `Program` alone is exactly the 17.5 stale-view trap (gotchas 2026-09-11). One refinement: the host should also refresh `now` in `.onChange(of: selected)` when it becomes `.home` (Program does this for the same reason, `ProgramView.swift:47-49`): the app can sit on the Program tab across midnight, and Home's own `onAppear` would then use the new day while the host still names yesterday's `firstMissed` until the next foreground. `now` refreshes in a handler, never in `body`.

**NB2 — `missedPromptEnabled: Bool?` has a dead value (§4.4 DEBUG).** With nil = normal and false = suppressed, `true` is never set. Acceptable to keep the house nil-by-default `@Entry` shape (INSIGHTS Patterns 2026-09-11) as long as the host reads `enabled != false`. The scan (AC-26) should mirror `RestNotifierSourceTests.silentOnlyInSeedBranch` (`/Users/zhabskyi/AppleApps/HomeGymLog/HomeGymLogTests/Static/RestNotifierSourceTests.swift:24-34`): the `forcesMissedDayPrompt` token appears in `HomeGymLogApp.swift` only between `DebugSeed.parse(` and the seed branch's `#endif`, and `AppClock.swift` declares the `@Entry` on exactly one line with `= nil`. Note `forcesMissedDayPrompt` currently reads `self == .missed` (`DebugSeed.swift:143`) and `DebugSeedTests.drafts` (`/Users/zhabskyi/AppleApps/HomeGymLog/HomeGymLogTests/Seed/DebugSeedTests.swift:57-63`) pins it; the repurposing to "the missed family" is fine, the test's loop just excludes the new cases as the spec says.

**NB3 — Copy the probe's exact modifier order in `ShellView`.** The real chain is `.safeAreaInset(...)`, `.ignoresSafeArea(edges: .bottom)`, `.background(...)` (`/Users/zhabskyi/AppleApps/HomeGymLog/HomeGymLog/App/ShellView.swift:25-29`); the researcher's measured card geometry (44 pt from the edge, bar covered) was taken with `.overlay` at a specific position in that chain (`scratchpad/probe/HomeGymLog/App/ShellView.swift`). The plan should place it where the probe did rather than re-derive.

**NB4 — `ProgramStore.shift(rows:)` must receive the program's complete session set.** Both callers pass their whole-program query, but the writer silently produces a partial map if handed a subset. Say so in the doc comment; a persistence test with a subset of rows is cheap. Prefer `rows` over `slots(of: program)` for symmetry with `start(sessionIndex:rows:)` and so the rows mutated are the instances the screens hold.

**NB5 — The Home fingerprint includes `scheduledDate`, so a shift re-runs `finishedLogs` (~0.4 s at program end on 17.5) synchronously on the main actor** (`/Users/zhabskyi/AppleApps/HomeGymLog/HomeGymLog/Models/HomeSnapshotBuilder.swift:33-35`). Because every tab stays mounted, a Program-card shift triggers it while the Program tab is running its follow-today scroll. The spec accepts it; record that finished logs cannot change on a date change, so a later slice may narrow the fingerprint to `index|statusRaw` (INSIGHTS 2026-09-11 explains why set-level fields are already omitted).

**NB6 — One possible overlay frame on `-seed missed -tab program`.** `RootView` applies `initialTab` in `.onAppear` (`/Users/zhabskyi/AppleApps/HomeGymLog/HomeGymLog/App/RootView.swift:35-42`), so the shell's first frame may have `selected == .home`. Screenshots are taken ≥ 2 s later; harmless, but do not write an XCUITest that asserts "no overlay ever" on that launch.

**NB7 — Handler placement.** Keep `onShift`/`onSkip` in `ProgramView` beside `start` and thread them through `ProgramContent` → `SessionCard` like `onStart` (`/Users/zhabskyi/AppleApps/HomeGymLog/HomeGymLog/Features/Program/ProgramContent.swift:57-61`). `SessionCard` already receives `state`; derive the two buttons from `state == .missed` rather than adding a second Bool next to `showsStart`. The Home host calls the same two writers; no shared "action" abstraction is needed for two call sites.

**NB8 — `-seed missed-shifted` writes through `ProgramStore.shift` inside `makeContainer`.** Good (seeds only use store functions). Note the seed then leaves `mainContext.hasChanges == false` (a successful save), so nothing of the failed-save order matters there.

**NB9 — After B1, §4.1 "Shift inputs … `ProgramStore.slots(of:)` or the query rows"** should name one (rows, NB4), and §3 "Program, Missed card" should read "Shift → write → selection follows today only when something moved".

## Decisions to record in `insights/INSIGHTS.md` (once the spec is revised)

1. **Missed-prompt host**: a view in `ShellView`'s `.overlay` (after `.safeAreaInset`) that owns the third `PlannedSession` `@Query`, its own `now` (appear, scene-active, and on the Home tab being selected) and the silence `@State`; keyed `.id(program.id)`; show = `enabled != false ∧ selected == .home ∧ MissedDay.shouldPrompt`. Silence lifetime = shell mount (dropped by the workout route flip by construction). Duplicating the query is deliberate; the shell never becomes a query owner.
2. **Derived overlays are never "closed before the write"**: NB4 (close, then write) applies to UIKit sheets only. A failed shift/skip leaves the prompt up.
3. **Engine `shiftMap` is total**; `[:]` means "not a missed session". Store writers return what they applied; screens treat an empty result as a silent no-op and a throw as a failed save (matches `start` returning nil).
4. **A Program-card shift sets `.followToday` directly** (plus `now` and `scrollToken`), not `reset`, which would re-apply the DEBUG preselection.
5. Whichever of B5's two shapes the probe settles (host-owned handlers on a concrete root, or `ShellView`-owned `now`), with the probe result.
6. The drag-on-card semantics from B6's probe (buttons never fire from a drag; or drag limited to the text block).
7. The new seed for the three-missed state, if B4 is resolved that way.

Nothing in the spec adds a dependency, entitlement, capability, backend, analytics or schema change; pounds, the static library, persisted sessions, immediate writes, pure Engine and `@Query` reads are all respected.
